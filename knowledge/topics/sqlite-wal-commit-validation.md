# SQLite WAL：有效帧、提交边界与记录计数

- 整理/访问：2026-11-17，Codex；适用：未加密 SQLite WAL 的格式检查与取证解释。
- 来源/作者：SQLite 官方，[Database File Format，4.1—4.5](https://www.sqlite.org/fileformat2.html#wal_file_format)；页面标注最后更新 2025-12-25。阅读范围仅 WAL 格式、校验和、检查点、重置与读者算法。
- 状态：官方文档核对＋下述自制数据验证；没有原始检材复验。

## 官方格式要点

WAL 含32字节文件头；每帧为24字节帧头及一页数据。帧头偏移4的数据库页数非零标记事务提交。有效帧要求 salt 匹配、累计校验和正确；校验使用的字节序由 magic 决定，不能与头字段的存储字节序混同。重置可能留下旧尾部；读取快照按提交边界选择各页的最后有效版本。详见上述官方章节。

## 本次自制验证

使用 Python 标准库 sqlite3（SQLite 3.50.4），临时建表并对同一主键先后写入两次；保持连接打开，读取其生成的 WAL。仅操作新建无敏感数据，未打开任何案件检材。

| 变体 | 连续有效帧数 | 最后提交帧 | 解析停止原因 |
| --- | ---: | ---: | --- |
| 原样基线 | 4 | 4 | 文件结束 |
| 最后一帧页数据翻转一位 | 3 | 3 | 累计校验和不符 |
| 最后一帧 salt 翻转一位 | 3 | 3 | salt 不符 |
| 尾部截断一字节 | 3 | 3 | 帧不完整 |

四项断言通过。页大小4096；基线页号为1、2、2、2，有三个提交标记，而 SQL 活动表只有一行。这个样例直接说明帧数、提交次数、当前记录数不能互换。验证程序和结果仅保留在本地本轮学习目录的 `wal_probe.py`、`wal_probe_results.json`，临时数据库已由程序清理。

## 后续任务的使用方式

1. 在可写工作副本分析，保留数据库与伴随文件的来源关系；原检材只读。先登记解析器和 SQLite 版本、页大小、文件长度及对应数据库。
2. 按帧顺序保存字节偏移、页号、提交页数、salt/校验结果，分别记录有效前缀终点与所选提交边界。异常后的碎片单列候选，不把扫描得到的页自动纳入活动快照。
3. 恢复表记录后再核对表结构、主键和业务事件；同一页或主键的多版本不得直接算作多次用户操作。
4. 报告明确“结构有效”“位于所选已提交快照”“业务含义已核验”的不同层次，校验和通过本身不证明数据来源真实。
