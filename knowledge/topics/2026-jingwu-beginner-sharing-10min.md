# 精武杯取证入门操作讲稿

【0:00—0:20 开场】

大家好，今天直接拿精武杯的题目讲操作：先查系统和数据库，再看安装包，最后用Wireshark分析流量。屏幕上的路径和过滤语句可以记下来，练习时照着找。

【0:20—2:00 查系统版本和文件配置】

拿到E01镜像，先用火眼导入，等解析完成，再进入文件浏览。下面打开的都是检材里的文件。需要导出时放到工作目录，用副本分析。

先做服务器第五十九题，查系统版本。进入根分区，打开etc目录里的os-release，找到PRETTY_NAME这一行，值是Ubuntu 22.04.5 LTS。如果这里是链接，就继续找到usr/lib/os-release。把字段和文件路径一起记下来，这题就有依据了。

第六十题问根文件系统的UUID。还是在etc目录，打开fstab。这里会列出分区挂载信息，找到挂载点是一个斜杠的那一行，再读取这行前面的UUID。别看到第一串编号就抄，先确认它对应根目录。

计算机第二十九题问WSL软件版本。找到Program Files下面的WSL目录，导出wsl.exe，在Windows里查看文件属性中的详细信息。文件版本和产品版本都是2.7.14.0，这个数字才对应题目问的软件版本。

再看语音识别服务。进入Users/pc/ASR，打开config.json。里面host是127.0.0.1，port是8765，组合起来就是屏幕上的地址。这个127开头的地址指本机，配置存在只能说明设置了这个地址，服务是否成功运行要另外查。

【屏幕显示，不朗读】
```text
服务器：/etc/os-release → PRETTY_NAME
根文件系统：/etc/fstab → 挂载点为 / 的行 → UUID
计算机：Program Files/WSL/wsl.exe → 文件版本、产品版本
ASR：Users/pc/ASR/config.json → host、port
http://127.0.0.1:8765
```

【2:00—3:20 读数据库和统计数量】

服务器上的小皮面板，数据在/xp/db/app.db。先导出这个文件，同目录下如果有同名的-wal、-shm文件，也一起保留，再用SQLite查看工具打开分析副本。

看左边的数据表。panel_cfgs保存面板配置，找到Entry记录，读对应的value字段，就能定位安全入口。users是用户表，里面有username和password字段。公开展示时把入口和密码相关值遮住，只讲表名和字段。

数据库题先看表结构，再按题目选字段。不要因为字段叫password，就直接把里面的一串字符当成明文口令。

统计题也一样，要先看具体内容。打开Users/pc/ASR/models，可以看到Qwen3-ASR-1.7B、SenseVoiceSmall和fsmn-vad。前两个做语音识别，最后一个检测语音片段，所以语音识别模型算两个。

服务器插件数量则去看.dsh/profiles/web/package.json，数dependencies里的用户插件，共五个。bundles里的两个内置模板另列，不算进去。

【屏幕显示，不朗读】
```text
/xp/db/app.db → panel_cfgs → Entry记录及value字段
/xp/db/app.db → users → username、password字段
/opt/dsh/dsh-home/.dsh/profiles/web/package.json
dependencies：5个用户插件
bundles：2个内置模板，不计入用户安装数
```

【3:20—6:10 看安装包和程序代码】

APK是安卓安装包。用JADX打开，先看AndroidManifest.xml，找Application和入口Activity。然后进入对应类，沿初始化方法往下看，查看代码准备启动哪些服务、调用哪些方法。

如果只看到少量加载代码，业务代码迟迟找不到，要考虑程序做了加固。后面的功能题需要使用脱壳后的代码，别一直在外层加载器里搜。

以第一百一十九题为例，题目要找保存锁屏记录的文件。在JADX里打开已脱壳的DEX，全局搜索.db，找到allpwd.db，再查看这个字符串在哪里被引用。接着进入调用它的方法，检查数据库打开和数据写入的逻辑，确认记录内容是否对应题目。

搜到文件名以后，继续往下看使用它的代码。文件名给了查找方向，具体读写逻辑才能说明用途。当前只能定位到相关代码，测试未完整运行，不能说已经实际采集到锁屏密码。

HAP和IPA分别是鸿蒙、iOS应用包。先复制一份，把副本后缀改成zip再解压。看鸿蒙权限时，打开module.json，定位权限列表，逐项数，这个样本申请了三项权限。

看iOS构建信息时，在解包目录找到Info.plist，用支持plist的编辑器打开，查看构建信息。这里要读的是保留的官方原版构建时间，2026年8月5日20点34分15秒，不能把它说成后来二次打包的时间。

如果题目问插件里的地址，先找Frameworks里的dylib文件，再用IDA打开对应文件，检索相关字符串。完整地址搜不到，就搜域名片段，查看使用这个片段的函数，有些地址是在代码中拼起来的。

恶意程序也可以从字符串开始。把题目里的ffmpeg程序放进IDA，打开字符串窗口，搜索out.exe，再查看引用位置。沿函数往上找，能定位到释放文件以及调用ShellExecuteW执行文件的逻辑。继续分析释放出的程序，可以追到解释器和au3脚本。

先把文件之间的关系画出来，再分析每一层做什么。需要观察运行时行为时，用隔离虚拟机配合Process Monitor记录文件创建和进程启动，不能在日常电脑上直接运行样本。

【屏幕显示，不朗读】
```text
JADX：AndroidManifest.xml → 入口类 → 初始化及服务调用
已脱壳DEX：搜索 .db → allpwd.db → 引用 → 读写逻辑
HAP：module.json → 权限列表
IPA：Info.plist → 官方构建信息
插件：Frameworks/*.dylib → 字符串 → 引用及拼接函数
IDA：out.exe → 引用 → 文件释放 → ShellExecuteW
```

【6:10—9:20 筛选流量并核对结果】

打开Wireshark，载入network_traffic.pcap。这个题目还提供了keylog.txt，需要在TLS设置中指定这份密钥日志，才能读取对应的HTTPS内容。密钥日志不要公开展示。

先做开放端口数量。把屏幕上的过滤语句粘到显示过滤栏。它筛选的是受害主机发回攻击端的SYN、ACK都置位的数据包，也就是连接请求得到的回应。

点开筛选结果，展开TCP，查看Source Port，也就是源端口。把不同端口记录下来，同一个数字重复出现只记一次。这里能得到22、80、443、3306、8080、8443，共六个。注意数的是不同端口，不是过滤后剩了多少个包。

接下来检查登录请求。用第二条过滤语句定位第63546和63548帧，分别查看请求与响应。前者是登录POST请求，后者返回401。再按同一登录路径把整组请求和响应对应起来，这组共有2048次尝试，对应响应都是401，没有显示通过这批请求登录成功。

不要只截图一条请求就结束。请求说明对方试图做什么，响应才告诉我们这次请求得到了什么结果。

再看上传文件的第一百五十九题。过滤到第79957帧，找到上传表单里的filename*字段。它写的是avatar_20260918%2Ephp，百分号2E还原成一个点，文件名就是avatar_20260918.php。遇到看着奇怪的文件名，先检查是不是做了编码。

第79959帧是上传响应，返回了一个网站资源路径。这个路径能说明网站用什么地址指向该文件，但题目如果问服务器硬盘里的绝对路径，还需要网站目录映射或文件系统记录。现有信息不能直接回答第一百六十五题。

再往后，第88417帧里有反向连接命令。可以从命令中读出目标地址和端口，但还要检查有没有对应的握手与后续通信。当前没有独立找到这条连接的握手证据，所以只能确认命令的目标。

每找到一条关键记录，就记下帧号，截图保留请求和响应的对应关系。以后复核时直接跳回这个位置，不用从十万多个包里重新翻。
