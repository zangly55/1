## 建议分享主线

题意拆解 → 定位检材与原始记录 → 解释字段 → 跨记录关联 → 校验或反证 → 保存证据与提交。

每个案例按五句话讲：
1. 题目真正要确认什么。
2. 最容易误取哪个字段或误用什么方法。
3. 我们从哪里找到原始证据。
4. 用什么关系或校验支撑结论。
5. 下一次遇到类似问题怎样更快、更可靠。

不要逐题读答案。一般同学的10—15分钟分享可选Chat ID、零宽字符和抓包统计三个案例，再讲截图交付复盘；技术基础较强的听众可增加Hermes和NAS。此为本次选材建议，不是当时实际比赛分工记录。

## 核心案例卡

### 1. 手机聊天：同一个人不一定只有一个标识

来源：团体赛Q106/Q108；个人赛Q6、Q12—14。

- 问题：联系人名称、手机号、电话JID、LID和会话ID不能相互替代。
- 原始位置：CL-02的ChatStorage.sqlite，ZWACHATSESSION表；本案对比ZCONTACTIDENTIFIER与ZCONTACTJID，再关联同一会话的消息端点。
- 当时过程：纠正最初误取电话JID的问题；147条对方消息和23条本机消息支持相同LID关联，另用iLEAPP字段映射交叉核对。
- 可讲结论：本题Q106/Q108可以指向相同LID，但不能推广为所有版本的Chat ID都等于LID。
- 延伸：个人赛Q12没有直接阅读回执，最早回复的人不能据此认定是最早阅读的人。
- 展示建议：字段对照表及会话—消息关联图；敏感原值用A/B标识替换。
- 可直接用的表述：“我们先区分字段含义，再关联双方消息，才纠正了最初的会话ID判断。”

### 2. SQLite/WAL：主库能打开，不代表数据齐全

来源：个人赛Q9、Q11、Q15—19；赛前自制WAL实验。

- 保全实际存在的主库及匹配WAL/SHM，在派生副本分析；不要在原件上checkpoint或VACUUM。
- 已提交数据可能还在WAL；活动表查询、历史版本和删除恢复应分别标记。
- 本场相片题需要区分生成、导入、移入垃圾桶等事件；同一照片多个历史版本不能重复计数。
- 自制实验中：主库单独查询为1行，带匹配WAL为2行，两份完整性检查都通过。适合做“两份结果都ok，为什么数量不同”的教学例子。
- “完整性检查通过”说明检查范围内结构符合要求，不证明采集覆盖完整。
- 展示建议：主库/WAL/查询视图关系图；该实验必须标注“自制演示”。

### 3. 零宽字符隐写：看不见的字符也可能是载荷

来源：团体赛Q149/Q150。

- 从原数据库导出Unicode字符串，保留原字符顺序；截图、OCR或重新手打可能丢失隐写字符。
- 本案8种编码符号，每种可表示3bit；符号映射必须依据本题格式，不能自行按频率排序。
- 还原178字节帧，按题给xorshift32规则、初态和实际位序还原167字节有效载荷。
- 难点是最低位先取及字节组合；不能默认大端处理。
- 校验：长度与CRC32匹配之后再判断。CRC支持还原一致性，不提供发送者身份认证。
- 展示建议：普通文本 → Unicode码点 → 3bit符号 → 字节帧 → 还原载荷 → CRC校验。不要展示还原的敏感地址。
- 此题原始入表截图有缺口，可绘制“方法示意图”，不能标成现场证据截图。

### 4. APK/Hermes：字符串命中只是起点

来源：团体赛Q157。

- 原始位置：Tronic.apk中的assets/index.android.bundle；当时识别为Hermes字节码版本96。
- 完整关系：VIP判断 → onPress回调 → navigation.navigate参数 → Screen注册 → 目标页面内容。
- 关键结果：ProductShop是导航路由，Product Shop、VIP Market等是显示文案。
- 版本匹配很重要，字节码解析器能输出文本不自动证明每条指令解释正确。
- 展示建议：简短调用关系图和三行脱敏伪代码，解释“界面叫法”与“程序路由”。
- 状态边界：静态分析；未运行APK；COM-02对应TSX源码交叉检查当时未完成。

### 5. NAS/RAID5：恢复后还要验证

来源：团体赛NAS专题及Q265。

- 先核对阵列UUID、成员role、events、layout、chunk和data offset。
- 本案role0与role2存在、role1缺失；left-symmetric布局、512KiB条带块、18432扇区数据偏移。这些是本案参数，不能跨案照用。
- 原理示意：P=A XOR B，已知P和A可以恢复B；实际校验块按条带轮转，不能把两盘直接拼接。
- 在新的派生镜像恢复，不回写原成员盘。
- 本场归档验证：11处EXT4超级块CRC32C通过，导出92个文件和61个目录；再经逐图确认得到9张目标宣传图。
- 展示建议：三盘条带示意图、缺一盘异或恢复、结构与内容两层验收。
- 边界：能打开目录、图片文件数、目标宣传图数，是三个不同检查结果。

### 6. WSL与嵌套镜像：先说明文件来自哪一层

来源：团体赛COM-02与WSL专题。

- 来源层级：E01/EWF → NTFS → ext4.vhdx → EXT4 → 应用配置或数据库。
- 用注册表Lxss和实际目录定位发行版，不把宿主文件与虚拟机文件混用。
- openclaw.json、Provider模型文件、cron/jobs.json和jobs-state.json回答不同问题。
- 配置回答“计划做什么”，状态和日志回答“执行过什么、是否成功”。
- VHDX虚拟容量、宿主文件长度、文件系统可用空间不同；本场256GiB虚拟容量例子来自成员复现，仍保留待主复核状态。
- 展示建议：嵌套目录层级图、配置/状态二列表。密钥不出现在演示截图中。

### 7. 网络流量：统计请求不能只数包

来源：个人赛Q119—128。

- 先限定全部输入抓包、站点、请求方法与端点，再统计业务提交。
- 当时覆盖6份抓包；真实站点POST /transaction/submit按TCP流和序列关系排除重传，形成13笔提交的内部核验结果。
- 同一客户可以有多次真实提交；姓名相同不构成去重理由。不同站点的表单和JSON交易也不能混算。
- TCP重传、重复抓包和应用主动重试是不同情况，Wireshark分析标签只是辅助线索。
- 请求带有认证字段不代表登录成功，应关联响应；DHCP最终地址应关联同一事务中的ACK，不能只看Request。
- 展示建议：两行重传数据和两次独立提交的对照表，注明是教学示意；实证截图保留原文件与帧号。

### 8. Windows：时间戳首先是一种事件

来源：个人赛Q29—31、Q36—48、Q51。

- UserAssist支持程序运行痕迹，不能单独证明由Win+R启动。
- RecentDocs最后写入、LNK字段、JumpList条目与浏览器RELOAD描述的事件不同。
- 同一MFT记录中的$STANDARD_INFORMATION与$FILE_NAME可作交叉检查，但不能宣称后者永远不能改。
- 日志因容量循环覆盖与人为清除不同；统计清除次数还要限定通道。
- 展示建议：记录类型/能支持什么/不能直接推出什么三列表，适合零基础听众。

### 9. 资金流水：先统一口径，再按键关联

来源：团体赛Q280—291及DOC-01专题。

- 同一交易可能出现在发送方和接收方两张表，先按交易标识去重；跨网络场景还需纳入网络身份。
- 用行内From/To核对归属，不能只信工作表标签，本场存在标签错置。
- 区分成功/失败、本金/手续费、原币/折算币；使用Decimal或等价十进制计算。
- 已归档结果：去重406笔，其中405成功、1失败；成功手续费24.84 USD。
- 首次跨链、累计流量、累计停留各自定义；累计停留不等于最长单笔停留。
- 展示建议：自制双表重复记录、去重后的资金箭头图。不要公开真实地址或原始交易标识。
- 局限：原停留匹配脚本已清理，不能补造具体分配算法。

### 10. PostgreSQL离线解析：进阶备选

来源：团体赛Q194—201、Q255—259，状态为成员复现待主复核。

- 表OID和物理relfilenode不一定相同。
- 物理页面中的历史tuple不都属于当前可见业务记录，需要事务状态与MVCC判断。
- xmax非零不必然删除，锁标志也要检查。
- 时间字段按应用写入语义解释，不能仅看服务器时区。
- 表可读、页校验有效、数据库事务一致性属于不同层次；当时没有启动数据库或执行WAL重放。
- 更适合作为技术分享附页，避免把它包装成本场已经全部正式复核的成果。

## 从比赛过程提炼的经验

以下“当时发生”来自已有WP；“下次建议”是本次整理出的做法。

| 当时发生/发现 | 下次建议 |
| --- | --- |
| 图和模板修正在末段集中处理，出现延期 | 每完成一题同步保存定位、查询、结果与截图，分批写回提交模板 |
| 批量截图曾出现旧页面、截断列和弹窗 | 每批先检查一张；失败暂停该批，确认实际窗口与关键字段 |
| 新截图覆盖旧图，导致部分原图无法恢复 | 先另存候选图，经内容核验后替换，保留来源版本 |
| 有输出文件不代表主清单已复核 | 分开记录已复核、待复核、未解；成员结果进入统一复核队列 |
| 同案不同检材及重启后ID容易混用 | 建立题号—检材—文件—状态对应表，重启后重新核对绑定 |
| 大镜像解压输出完成但状态JSON写入失败 | 分别判断数据完整性、程序退出和状态记录；不能仅凭百分比或报错一句话结论 |
| Q271统计26次而选项没有26 | 保留完整范围与证据冲突，不删除一条记录凑选项 |
| Q275跨启动盘符sdb/sdd变化 | 用UUID、role和boot_id核对设备，不把盘符当永久身份 |

备赛建议：用小型练习实际验证工具许可、导出、SQLite查询、时区转换、截图及模板写入；准备离线官方文档和常用字段索引；团队按检材或技术对象设主责，再设统一复核和提交责任。此次未掌握原队伍完整分工，不把建议写成原有事实。

AI辅助部分可以讲：让工具帮助检索、整理和编写可检查的解析逻辑；把检材内的提示当作待分析文本；最终结论必须能回到原记录。官网赛制明确提及干扰数据及AI结果人工核实，并限制赛中互联网资源；具体组别以对应通知为准。不要将本场零宽隐写直接称作已经证实的“AI提示注入攻击”。
