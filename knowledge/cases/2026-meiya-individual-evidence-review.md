## 已验证的方法与适用边界

### 导入与挂载身份

原始材料按真实文件类型分类，镜像、手机资料、录屏和独立内存材料分别登记。WKH-03 内发现的六份有效抓包文件经导出后分别作为新检材导入，并记录父检材标签、源虚拟路径、导出副本与子检材编号的对应关系。文件扩展名本身不能证明一个应用缓存是独立检材。

本轮 COM-01 解析完成后，普通 `status` 仍只返回旧挂载列表；同一案件绑定下使用 `--no-daemon` 后返回新增挂载，随后能够读取目标镜像原始文件。这次观察支持“CLI 守护进程上下文缓存陈旧”的诊断；它不意味着所有缺少挂载的问题都能用该选项解决，也不代表需要重新导入。参数位置和命令用法见 [GES 通用流程](../topics/ges-windows-forensics-sop.md)。

### 手机数据库与删除记录：Q7、Q9、Q11、Q15—19

FC-01 的聊天数量按实际消息记录及稳定消息标识统计，并与方向字段交叉检查；界面计数器不能直接替代题目要求的消息事件数。

相片分析保留未经数据库连接打开的 `Photos.sqlite` 及 `Photos.sqlite-wal` 原样副本，另建分析副本。活动表与 WAL 历史记录分别检查；对恢复记录保留页号、帧号、字节偏移、表结构映射，并核验 WAL 盐值与校验和。截图来源字段在活动记录和已删除残留中均有命中，因此仅查活动表会漏计。时间字段保留原始纪元与小数秒，再按题目要求转换时区和显示精度。

证据定位为 `PhotoData/Photos.sqlite`、`PhotoData/Photos.sqlite-wal` 中的 `ZASSET`、`ZADDITIONALASSETATTRIBUTES`、`ZCLOUDMASTER` 等记录。本页不公开具体相片标识、云端唯一标识或账户信息。某一应用确有 WAL，不证明其他应用也存在可恢复的 WAL。

### Windows 原始记录交叉复核：Q25—35、Q38—43、Q51—65、Q71

- SAM 用户记录与 SOFTWARE 配置文件列表按 SID/RID 关联；读取二进制注册表值时关闭解析库的默认截断。名称解码为空时应先检查导出或展示是否截断，不能直接判定原数据为空。
- Q29—30 对原始 `System.evtx` 中的日志清除事件继续读取被清除的目标日志通道与执行账号；不能把所有同类事件 ID 的出现次数当作某一指定通道的清除次数。
- Q31 将安全日志容量上限、保留策略与文件实际容量对照。历史记录缺失不自动等于人为清空。
- Q34—35 先锁定目标用户 SID 对应的回收站目录，再完整解析其中的 `$I` 元数据，按删除时间排序；不能混入其他用户或仅按原路径中出现的用户名过滤。
- Q38—40 区分网卡配置中的覆盖地址、解析记录中的物理地址和无线网络配置标识，不能混为一个字段。
- Q42 对同一 NTFS 记录的 `$STANDARD_INFORMATION` 与 `$FILE_NAME` 时间分别读取并核对路径。两者有差异时保留原始值和属性来源，不把被修改的高层属性时间直接当作原始创建时间。
- Q43 依据文件魔数和实际图片解码结果判断格式，不能只看扩展名。
- Q51 排除后续升级时间，结合初始安装相关文件和目录的 NTFS 元数据核查最初安装日期。Q54—56 对浏览记录、自动填充及登录记录先限定用户，再核对各浏览器数据库清单和统计覆盖。
- Q63—65 区分程序点击记录、应用启动日志、视频设备枚举和虚拟摄像头启停记录，避免用相邻但含义不同的时间代替题目所问事件。

本地凭据题只在授权检材的离线副本中验证；公开归档不包含口令、提示、密码哈希或任何可用于认证的原值。

### 无线操作日志的统计单位：Q75、Q81—92

WKH-02 中，时区符号链接导出不能得到有效文件内容时，使用已解析的时区记录与带偏移的系统日志交叉确认，并明确记录这项读取限制。

无线操作分析区分配置界面、目标选择、实际进入运行循环及提前退出。按题目分别统计运行时出现的不同信道、保留重复项的先后序列、以及包含真实运行标记的独立会话文件数。同一文件多次进入循环不等于多个文件；输入过目标设备也不等于已经进入运行阶段。统计以完整会话文件清单为范围，保留未进入循环的文件及排除理由。

### Linux 配置、首次初始化与表达式：Q97、Q104—116、Q118

Q97 将发行镜像参考日期、首次初始化日志、已有实例的后续启动及软件部署记录分开。结论以首次初始化完成记录等交叉支撑，不单凭一个构建日期推断设备首次部署。

配置文件中的参数和源代码分支可以证明配置内容或条件行为；是否实际监听、实际加载或实际执行仍需运行记录。Q112 中被注释的表达式可按题目给定条件计算展开结果，但不能据此宣称该表达式在检材系统中生效。Q103、Q117 在冻结清单中仍存在运行状态或实现版本之间的冲突，只保留为待复核候选，未提升为已核验答案。

### 抓包中的认证、交易与地址分配：Q119—128

- Q119 从原始 HTTP 请求负载提取的是被捕获的认证字段；相邻响应为 HTTP 401。成功捕获请求与成功登录是不同事件，不能把捕获到的字段宣称为已验证有效的管理员凭据。
- Q120—121 先界定题目指定的真实网站、目标端点和 HTTP POST 请求，再按捕获文件、TCP 流及序号检查重复与重传。同一客户在不同连接中再次提交的请求不能仅因姓名相同而合并；另一个仿冒站点的 JSON 交易不并入真实网站付款统计。逐条请求与响应的关联留在本地审计表。
- Q122—125 的身份、付款和客户端字段仅留本地；公开方法保留“表单解码、同一请求内关联、客户端环境特征核查”的流程。
- Q126 从实际 mDNS 服务公告的 SRV 记录读取端口，不能套用软件常见默认端口。
- Q127 按请求的内容类型和实际负载结构判断编码格式。Q128 关联同一 DHCP 事务的请求、客户端标识与 ACK，最终指派地址以确认响应为准。
