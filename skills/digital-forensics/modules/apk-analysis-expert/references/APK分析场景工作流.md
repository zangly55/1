# APK 分析场景工作流

本文件只补充问题场景、最小 Skill 路由、证据升级和完成标准。产品命令、授权、任务复用、分页、重试和停止由对应 AppAnalyzer Skill 或运行时负责；专家只提交分析目标、证据缺口、必要作用域和用户交互要求，并消费公开结果。

## 静态快速分诊

适用于确认 APK 身份、签名、组件、权限、第三方线索和加固状态。

- 路由：使用 `thunder-app-static-analysis`；缺少或不确定 `aid` 时由该 Skill 定位证据，不猜测 ID。
- 证据：只根据 Skill 返回的公开结果和边界建立 E1 事实；加固、动态加载、Native 或敏感权限只建立待验证项。
- 完成：输出身份、文件、签名、权限、SDK/线索、加固和分析状态，每项结论引用可定位来源。

## 源码、接口、鉴权和加密

适用于分析接口实现、Token 来源、签名/加密、数据库、Native 或业务调用链。

- 路由：消费已有且匹配当前 APK 的 E1 基线；缺少时使用 `thunder-app-static-analysis`。随后使用 `thunder-app-source-reverse`；源码被加固阻断时转 `thunder-app-unpack`，产物可读后回到源码 Skill；运行时参数不确定时转 `thunder-app-frida-validation`。
- 证据：源码或产物直接确认的内容为 E2；代码具备能力不等于本次运行发生，需要运行事实时选择动态、抓包或 Frida。
- 完成：形成可定位的入口、参数构造、调用链和源码边界；无法确认的参数标记 `unknown` 或明确为代码能力，不写成实际行为。

## 加固识别与脱壳恢复

适用于确认加固阻断原因，并在必要时取得可供源码分析的运行时 DEX/SO 产物。

- 路由：使用 `thunder-app-unpack`；产物可读后转 `thunder-app-source-reverse`。
- 证据：专家只消费 Skill 返回的预检、执行状态、产物和边界；需要受控操作时由 Skill 或运行时处理。
- 完成：只报告实际返回的加固信息、执行状态和 artifact；产物缺失、源码不完整或任务仍运行时披露边界，并决定继续请求结果、阶段性交付或人工复核。

## 隐私与运行时行为

适用于判断本次运行是否读取通讯录、设备标识、定位、相册、文件或执行高风险设备操作。

- 路由：消费已有且匹配当前 APK 的静态基线；缺少相关上下文时使用 `thunder-app-static-analysis`。使用 `thunder-app-dynamic-monitor` 获取运行观察；需要 Key、明文、参数或 Native 细节时转 Frida。
- 交互：向动态 Skill 提交目标行为和需要用户完成的交互；任务复用、受控执行和结果读取由 Skill 或运行时负责。
- 完成：分别输出“声明”“本次观察到”“未观察到/未知”；只按 Skill 返回的设备、版本、时间、交互范围、执行状态和完整性边界解释结果。

## 网络通信与数据流向

适用于判断端点、请求响应、敏感字段和数据来源，以及是否满足数据上传或外传结论条件。

- 路由：已有抓包结果足以回答时直接使用 `thunder-app-network-capture`；缺少端点或数据来源关联时使用 `thunder-app-source-reverse` 补证；TLS 或运行时参数不可见时转 Frida。
- 交互：向抓包 Skill 提交端点、字段和交互目标；抓包任务、正文采集和受控执行由 Skill 或运行时负责。
- 完成：区分源码端点与实际请求，按 `证据等级与结论语义.md` 区分通信、敏感字段、数据来源关联和政策不匹配，并披露代理、TLS、正文截断、扫描上限、交互覆盖和任务处置边界。

## Frida 运行时参数验证

适用于静态、源码或普通动态证据不足时，定向确认 Key、IV、明文、密文、SQL、Native/JNI 或 TLS 参数。

- 路由：使用 `thunder-app-frida-validation`，专家只提交能够回答当前问题的最小验证目标、预期观察和用户触发操作。
- 边界：能力选择、预检、脚本集合、授权、任务复用、结果读取和停止由 Skill 或运行时负责；不为泛化探索请求 Hook。
- 完成：区分 Skill 报告的实际 Hook 观察、脚本错误、无输出和推断；敏感值最小化展示，记录触发路径、样本范围、未触发路径、执行状态和边界。

## 综合研判

适用于基于当前证据生成可复核的 APK 综合结论，而不是无条件执行全部高成本能力。

- 路由：先消费已有静态 E1 基线，缺少时补充静态分析；再按问题缺口选择源码 E2、脱壳、动态/抓包 E3 或 Frida。
- 审查：汇总产品 Skill 的公开结果，在专家证据索引中记录来源引用、artifact、事实、错误、冲突和边界。E4 只能由专家审查生成，并引用至少一个 E2 和一个 E3。
- 完成：每条发现分开记录事实、解释、风险、证据等级和建议，并定位到 Skill 公开结果、源码或 artifact。受控操作未获批准、环境不可用、动态未执行、任务仍运行、结果截断或证据冲突时，输出相应降级结论和补证路径。
