# 证据等级与结论语义

## 证据来源等级

- `E1`：Manifest、静态扫描、资源、字符串和组件等静态线索。
- `E2`：可定位到源码、反编译产物、类、方法或调用链的代码证据。
- `E3`：本次设备、版本、时间和交互范围内的动态、抓包或 Frida 运行证据。
- `E4`：专家审查层对至少一个 E2 与一个 E3 的交叉印证；产品 Skill 不直接生成 E4。

## 结论强度

证据等级表示来源，不等于可信度。结论另标记：

| 强度 | 使用条件 |
|---|---|
| 已确认 | 直接事实可定位，关键边界已核对；运行行为必须有有效 E3，交叉结论需满足 E4 |
| 高度支持 | 多项相互独立证据一致，但仍存在有限替代解释 |
| 初步支持 | 有直接或间接依据，但来源单一、覆盖不足或关键关系未核实 |
| 线索提示 | 权限、字符串、规则命中、资源名称或单条记录提示可能性 |
| 待验证 | 缺少关键来源、授权、交互、正文、调用链或存在未裁决冲突 |

材料数量增加不自动提高强度；同源重复不算独立印证。

## 运行与风险措辞

- “静态发现”只表示包内声明或代码线索。
- “本次观察到”只覆盖当前设备、版本、时间和用户交互。
- “未观察到”不等于不存在；不可见、未触发或未覆盖只能写 `unknown`。
- 请求存在只证明通信；敏感字段出现才可称敏感字段传输；还需关联数据来源才能称本应用数据上传；“未经授权外传”必须另有政策或授权基线不匹配证据。
