# 跨 Skill 状态传递

专家只消费前置 Skill 已提交的公开结果和证据缺口清单，不读取隐含会话记忆。传递关系如下：

| 上游 | 专家消费的公开结果 | 可支持的后续判断 |
|---|---|---|
| static-analysis | cid、aid、包名、版本、哈希、平台、加固线索、E1 facts | source/unpack/dynamic/capture |
| unpack | 执行状态、artifact 引用、DEX/SO 产物事实和边界 | source-reverse |
| source-reverse | 文件路径、类/方法、调用链、E2 facts、warnings | dynamic/capture/frida |
| dynamic-monitor | 运行事件、时间、类别、交互覆盖、执行状态和 E3 边界 | report/frida |
| network-capture | host/IP、协议、摘要、正文可见性、执行状态和 TLS 边界 | report/frida |
| frida-validation | capability、goal、已治理的观察事实、执行状态和敏感材料边界 | report |

交接时同时更新 `gap_id`、输入 `evidence_id`、待验证假设、预期观察、用户操作、执行条件和完成条件。专家只提交分析目标和必要作用域，不向下游注入专家状态或代替产品 Skill 管理授权、命令和任务。下游返回后必须回填“证实、证伪、部分支持、冲突、阻塞或人工复核”。

`blocked` 只传递阻塞原因和解除条件；`partial` 可以进入审查，但不能作为完整覆盖。切换 Skill 必须引用明确的证据缺口和来源结果；没有问题来源的下游任务不能请求执行。
