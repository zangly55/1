# 附件清单与交付前检查

## 一、附件清单

只列实际存在或用户明确确认将补充的附件：

| 编号 | 附件名称 | 来源或生成方式 | 时间 | 对应正文 | 文件或载体位置 | 哈希或标识 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  | 已提供 / 待提供 / 无法读取 |

常见附件包括现场照片、屏幕截图、录屏、取证工具日志、任务结果文件、提取固定清单、检材或载体照片、封存移交记录和完整性校验文件。不得为了表格完整虚构附件编号。

## 二、提取固定清单

| 编号 | 数据来源 | 数据类别或名称 | 时间范围 | 数量或大小 | 输出位置或载体 | 算法 | 校验值 | 对应附件 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  |  |  |

数据来源、输出对象和校验对象必须明确，不能仅写“相关数据”“已提取完毕”。

## 三、一致性检查

交付前至少核对：

- 文书标题、案件类型、任务范围与单位模板匹配。
- 取证人员、其他在场人员及其角色在首页、正文和签名栏一致。
- 起止时间、日志时间、照片截图时间和附件形成时间能够对应；冲突已列明。
- 设备、介质、检材、输出载体和附件编号前后一致。
- 工具名称和版本来自实际材料，不把产品系列名当成具体版本。
- 操作步骤与工具状态相符，没有把计划、失败或部分完成写成成功。
- 文件数量、记录数量、大小、路径和格式在正文、日志及清单中一致。
- 每个哈希值都对应明确算法和明确对象，值逐字符一致。
- 截图、照片、录屏和日志编号均能在附件清单中找到。
- 封存、移交、签名、拒签或见证内容只记录实际材料显示的信息。
- `〔待确认：字段〕` 已逐项处理，未处理项已在交付提示中列明。

## 四、交付状态

输出状态只能使用：

- **可供人工核对**：正文事实均有来源，仍需取证人员按原始材料逐项确认。
- **存在待确认项**：可以查看草稿，但不宜进入签字流程。
- **存在来源冲突**：应先核对原始记录、日志或设备时间。
- **材料不足无法起草**：缺少取证过程或关键对象信息，仅能提供空白结构。

不得输出“正式有效”“程序合法”“可以定案”或“已经审签”。
