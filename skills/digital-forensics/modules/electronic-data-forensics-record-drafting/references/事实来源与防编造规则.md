# 事实来源与防编造规则

## 一、事实台账

起草前建立内部事实台账，每项至少记录：

| 字段 | 内容 |
| --- | --- |
| 事实内容 | 人员、时间、地点、对象、动作、结果、数值或状态 |
| 来源类型 | 用户已确认、原始材料、机器结果、模型整理 |
| 来源位置 | 文件名、页码、日志时间、日志行、截图编号或用户消息 |
| 确认状态 | 用户已确认、原始材料记录、机器结果、待确认、存在冲突 |
| 可否入正文 | 可以、仅可作为待确认项、不可写入 |

“模型整理”只能重组已有事实，不能成为新事实的唯一来源。

## 二、可进入正文的内容

- 用户明确确认且与其他材料不冲突的事实。
- 原始任务书、审批材料、检材交接记录、现场记录等材料明确记载的内容。
- 工具日志、系统输出、照片、截图、录屏或哈希文件中能够准确定位的结果。
- 对上述内容所做的不改变含义的格式整理和时间顺序编排。

## 三、不得直接写入的内容

- 根据经验推测“通常会执行”的步骤。
- 从文件名、工具默认设置、目录结构或上下文猜测出的人员、设备、算法、路径和结果。
- 没有实际输出支持的“提取成功”“校验一致”“封存完好”“网络正常”等结论。
- 示例模板中的单位、人员、时间、设备、账号、文件数量和哈希值。
- 取证人员尚未确认的模型概括、法律判断和技术解释。

## 四、待确认与冲突

- 缺失字段写为 `〔待确认：字段名称〕`，不能用“某某”“XXX”、零值或示例答案代替。
- 两个来源冲突时并列列出来源和原值，正文对应位置保留待确认标记。
- 疑似日志时区、系统时间或人工记录错误时，不自行换算覆盖原值；可以另列换算结果供人工核对。
- 用户明确选择其中一项后，记录“由用户确认采用”，但不删除冲突提示。

## 五、过程表述

按“谁、在何时何地、针对什么对象、使用什么工具或方法、执行什么动作、得到什么实际结果”组织。未能从材料确认的环节不补写，失败、取消、中断和部分完成如实保留。
