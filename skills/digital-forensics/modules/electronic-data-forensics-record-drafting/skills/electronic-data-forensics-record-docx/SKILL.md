# 电子数据取证笔录 Word 成文

## 使用条件

当用户要求写、起草、生成、导出或下载电子数据取证笔录时使用。输入必须是已经由笔录草拟流程生成的完整 Markdown 草稿；本技能只负责排版和文件交付，不增加人员、时间、操作、结果、哈希值、签名或程序结论。

## 生成流程

1. 获取当前会话可写工作区。运行时存在专用产物目录时优先使用；否则在工作区创建 `outputs/`。不得把产物写入专家包目录或技能目录。
2. 将完整笔录保存为 UTF-8 Markdown 临时源文件。文件名格式为 `<文书类型>-<YYYYMMDD-HHmmss>.md`，时间部分读取运行时当前时间生成，不直接使用格式占位符；文件名不得包含真实案件秘密或完整个人信息。
3. 根据本 `SKILL.md` 的绝对路径定位 `scripts/md_to_gongwen_docx.py`，执行：

```text
python scripts/md_to_gongwen_docx.py <输入Markdown> -o <输出DOCX> --title <笔录标题>
```

实际执行时使用脚本的绝对路径。输出文件与 Markdown 同名，扩展名为 `.docx`。
4. 使用 Python `zipfile` 或 `python-docx` 验证输出是可读取的 DOCX，且至少存在一个非空正文段落或表格。生成失败时修复依赖、路径或源稿后重试一次；再次失败则明确报告错误，不得宣称已经生成产物。
5. 检查可读取的正文、表格和文档结构，核对源稿内容是否完整。只有运行时明确提供 DOCX 页面渲染与图像视觉读取能力，且实际成功读取页面图片时，才执行页面视觉检查；发现截断、重叠、表格溢出、缺字或异常空白页时，调整后重新生成并复查。只有渲染产物、OCR 文本或文件可读取性检查，不能据此宣称版面正常。未完成全部页面视觉检查时，交付说明已完成的检查范围，并提示“页面版式待人工复核”。
6. 将 `.docx` 保留为最终产物并在回复中明确文件名。Markdown 作为临时文件或可追溯源稿，不得用聊天中的长篇正文代替产物。

## 固定版式

- 纸张：A4。
- 页边距：上 `3.7cm`、下 `3.5cm`、左 `2.8cm`、右 `2.6cm`。
- 主标题：方正小标宋简体、22 磅、居中、固定 30 磅行距。
- 一级标题：黑体、16 磅，使用“一、”编号。
- 二级标题：楷体、16 磅，使用“（一）”编号。
- 三级标题：仿宋、16 磅，使用“1.”编号。
- 四级标题：仿宋、16 磅，使用“（1）”编号。
- 正文：仿宋、16 磅、首行缩进 2 字符、固定 28 磅行距。
- 表格：网格表，表头浅灰底，内容按单元格长度使用 12 至 14 磅字体。

字体在当前机器缺失时由 Word 进行替代显示，不能因此更改文书事实内容。

## 交付约束

- 用户允许“先写示例数据”时，标题应包含“示例草稿”，正文首部说明所有数据仅为演示用途。
- 存在 `〔待确认：字段〕` 时可以生成 DOCX，但回复必须标明“存在待确认项，不宜进入签字流程”。
- 不生成只有标题或空模板的 DOCX；材料不足时先形成包含待确认字段的可填写草稿。
- 不把 Markdown 代码围栏、YAML frontmatter、工具调用记录或模型思考写入 DOCX。
