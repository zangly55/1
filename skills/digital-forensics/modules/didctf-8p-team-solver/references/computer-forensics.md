# 计算机检材：加密依赖、定向提取与验证

仅在题目涉及磁盘/内存、多层加密、保险库或脚本混淆时读取。以下方法来自已完成案例的复盘，不预置密码、PIM、盘符或题库答案；具体格式仍须核对检材及所用解析器。

## 1. 先画依赖，再分配昂贵任务

- 用简表记录每层的输入、所需密钥、来源、执行者、验证方式和产物。例如磁盘/内存 → BitLocker 分区 → 保险库/VC 容器 → 脚本、压缩包、数据库；实际顺序由检材决定。将共用前置条件写入 prep.json，不让多名成员分别等待或重复破解同一层。
- 密钥发现与验证分开登记。新线索立即通知依赖它的任务；参考 WP 提供的密码也是候选，须对目标文件验证后才标 ready。开机密码、保险库主密码、VC 内外卷口令、数据库口令不得因字符串相同而自动通用。
- 大镜像哈希、内存扫描、整目录导出各指定唯一执行者。先复用已有任务与有效产物，再提交缺少的工作；长任务等待期间处理独立题，不能只轮询。
- 区分 E01 容器文件哈希、重建逻辑磁盘哈希和导出文件哈希。记录算法、对象、原始完整值及来源，再按题目截取；不能用对首个 E01 分段执行 Get-FileHash 的结果替代逻辑磁盘校验值。已有检材元数据/校验任务可用时先核验，不重复读取全盘。

## 2. 挂载身份与只读回退

- 后端任务 completed 或分区 decrypted 只代表该状态。继续核对 eid、原镜像路径、分区起始偏移/长度、实际文件系统、根目录及代表文件。盘符、卷名及目录可读不能单独证明身份。
- 路径指向宿主卷、分区大小不符或时间/目录明显不符时，立即停用该路由；按 [playbook.md](playbook.md#解密后挂载异常与复制冲突) 做有界核查并报告具体故障，不能宣称已经获得检材明文。
- 已授权的离线分析可由 GPT 登记独立只读解析作为回退：直接打开用户提供的原始镜像，不把 GES 虚拟路径转换成猜测的本地路径。记录解析器/版本、镜像身份、分区偏移/长度与产物清单，成员按分工复用。现有权限或用户限制仍适用。
- BitLocker 验证需目标分区密钥解封及合理文件系统；VC 验证需解密后的头部结构、头部/密钥区校验和及合理文件系统。可读的几个字节或任务返回码不够。CRC 是格式校验，不能称为密码学认证。
- 先识别文件系统再选解析器，Windows 检材内的容器也可能是 FAT32。优先读取所需头部、目录和文件流，避免为几 KB 证据先导出数 GB 容器。
- 替代产物已验证且旧复制不再需要时，只取消自己创建的任务并确认结束；残留标为 .partial 或明确不完整，从 ready 清单排除。记录实际读取范围、字节数；完整导出文件才记录其完整文件哈希，不能把局部流摘要称为全文件哈希。

## 3. 保险库、VC 与损坏的密钥文件

- 先确认保险库格式与版本。OPVault 案例可按 profile 中的 salt/iterations 派生密钥，并分别验证 master/overview 的 opdata01 HMAC 后解密；条目密钥及内容也按格式验证。使用已验证解析器或对照格式实现，不能只看输出像 JSON 就宣称密码正确。
- opdata01 的明文长度及填充遵循其格式，不能套用任意 PKCS#7 去填充。保留原始字段路径：条目字段的标题 t 与值 v 含义不同，即使密码误填在标题，也应记录实际来源，不悄悄修正原数据。
- 找到保险库条目后，按用途作本地验证，例如与目标用户 NT 哈希匹配、解开相应压缩包或验证容器头。不能用“成功打开保险库”替代其中每个口令的有效性验证，不尝试在线登录。
- VC 普通卷、隐藏卷及各自备份头按对应格式分别定位；不要在密文中搜索明文魔数来判断有无卷。外卷与隐藏卷可能采用不同口令/密钥文件组合，分别记录是否使用密钥文件及 PIM 来源；不照搬上次案例的参数。
- 密钥文件必须保留原始字节、实际检材路径和导出定位。截图、缩略图或重新保存的同一图片不等于原密钥文件。答案要求绝对路径时保留检材内路径，不用本机导出目录替代。
- PNG 高度异常时可结合 IHDR CRC、IDAT 解码和图片结构检验候选高度；只在工作副本修复，保留原件和修改字节说明。候选唯一性须在实际搜索范围内表述；图片能显示不证明能解 VC，最终仍以目标卷头验证为准。

## 4. 内存与脚本的定向分析

- Windows 控制台编码错误先检查输出通道；必要时以 UTF-8 重跑同一命令并保存输出，不因 GBK 编码异常重新复制整份内存。符号、扫描结果和缓存只有与同一镜像及配置匹配时才复用。
- 文件名线索用 filescan 与目标进程 handles 等记录关联；磁盘上的相似数据库名不一定是题问进程使用的文件。保存大小写、PID、对象路径及时间来源，不能把全局字符串命中当作进程归属。
- 系统 Build、关机时间和 MAC 各查对应原始记录。MAC 不能从 PCI/PnP 实例字符串推导；关机事件需判断是否正常关机并明确 UTC 换算，进程时间差需使用同一时基。
- 混淆脚本先静态写出每层变换及逆序：区分 Unicode 码点运算、UTF-8 字节运算、位置相关 XOR、Base64 与压缩。逆变换后按原算法重编码并与密文比较，避免只因出现密码样式就停止。
- 同目录的 .obf 和加密数据库备份可能使用不同算法。OpenSSL salted 备份需从加密脚本确认密码派生、摘要和加密模式；不要把 EVP_BytesToKey 与 PBKDF2 混用。解密后再验证压缩格式、数据库结构和目标字段，不执行来源不明脚本。

## 5. 输出最小化与复核

- 题目只问 API 密钥后几位时，在本地读取后先截取再输出；不能先打印完整配置，再只在最终答案遮盖。工具凭据始终不写入题解；题目要求的检材密码仅写入对应本地答案。
- 解密的卷头、密钥区及保险库明文可能包含额外秘密，保留在必要的案件工作文件中；共享日志只输出验证状态和题目所需字段，通用知识库不复制密钥材料。
- 同名记录、截断数据、参考答案分层和发布版本规则见 [verification.md](verification.md)。证据支持、参考一致与判题通过分别记录，不因已取得明文就自动完成所有关联题。

## 6. 跨检材解密与系统卷

- PC口令可能由服务器上的独立文件解密工具产生。由sudo/调用日志定位加密输入，再从对应工具镜像或脚本确定格式、密钥来源、nonce/tag切分及AAD；派生明文文件标明生成位置，不宣称它原本存在于PC。GCM标签验证通过后仍要验证该口令适用于目标卷。
- VC系统卷与普通文件容器的头部位置、加密区偏移、扇区编号基准可能不同。读取本卷头部参数，核对魔数、头/密钥区CRC及文件系统；XTS数据单元的绝对/相对编号由实际布局确定。不要固定复用历史头偏移、迭代次数或tweak。

## 7. 静态客户端与图片统计

- 先识别打包格式并读配置/字节码；解出后端URL或接口只能回答地址和接口行为，不能替代服务端业务记录。用户要求静态分析或只在检材内分析时，不运行客户端、不继续访问检材公网地址。不同服务器的数据未完成业务归属核对前不可移作缺失后端数据。
- 图片总数先区分普通目录实例、缓存/拖拽副本、内容去重数与题问对象。保存清单和去重规则；字节哈希相等支持重复，哈希不同不保证视觉内容不同。统计AI标识时检查实际内容及覆盖，不仅按目录名推定。OCR用于筛候选，关键号码、地址和最高频项再核对原图。
