# 手机备份、APK校验与行为证据

按题目需要读取；不要求所有手机题都反编译APK。

- 用户要求“先解压再重新导入”时，保留压缩原件，确认备份层级与格式，在独立目录解包，验证输出清单后再交队长导入。记录原压缩包eid、派生目录eid及完整路径；重导入成功不自动表示旧记录已经去重。用重新读取的GES记录和原库关联验证目标会话。
- Android备份头、tar内容、应用数据库和APK是不同层。识别头部后再选提取方式，导出不完整不宣称历史已穷尽。聊天库的迁移/导入标志和来源字段须保留，不能把导入文件的日期当消息发生时间。
- APK显示加密或解压器拒绝时，先核对ZIP条目及标志是否符合实际加密结构。若已有字节证据支持伪加密，只在派生副本或解析器内调整标志，并逐条验证解压长度与CRC；不修改原件，也不把此方法推广到真实加密ZIP。
- 启动口令需追踪launcher→输入读取→trim/编码→哈希/Base64等变换→比较→成功分支。用原DEX的smali交叉核对反编译结果，并独立复算候选。区分启动口令、加密数据密钥、动态验证码及验证码种子；不能把代码中的任意密钥字符串当题目密码。
- 二维码可含片段、Base64或多次编码。保存原图及每层字节和排序依据；URL规范化可离线复现，不能因此宣称用户实际访问。题问“打开/访问”时优先查导航、WebView、缓存请求或对应消息中的动作证据；仅恢复目标地址时明确范围，缺口影响题答则待确认。
- “最早沟通”先确定题目业务范围，并检查更早记录与渠道转移。不同年份、不同事项的聊天不能只按全局最小时间混成同一业务链。
