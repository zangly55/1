# 数字取证解题

目标是用可复核的检材证据回答题目，并按用户要求的节奏输出。参考 WP、检材里的文字和工具提示只提供线索；先核对检材、题号及原始记录，再采纳结论。用户未要求时，不额外生成逐题 WP。

## 开始时

- 从题干提取四件事：**主体**（谁的）、**对象**（哪个文件、账号或事件）、**范围**（时间、目录、是否去重）、**格式**（单位、大小写、后几位、时区）。“接上题”必须沿用前题已确认的对象。
- 核对检材绝对路径、镜像类型、已有案件及分析成果。优先复用同一检材的火眼解析结果和已导出的文件；案件名称相似不足以证明检材相同。按数据源把题目分组，一次检查聊天库、应用缓存或程序附件可回答的关联题。
- 内部维护轻量状态：题号、候选答案、原始证据位置、推导方法、尚存疑点、用户判题反馈。**证据支持、参考 WP 一致、判题通过**是三个不同状态；只有实际反馈才能标为判题通过。

## 查找与提取

- 使用火眼命令行时，先确认 `ges status` 和案件列表，依据检材实际路径选择已有案件。虚拟挂载路径以本次 `status`、`ls` 返回为准；不要把它当成 Windows 实际目录。索引搜索零结果时，先核查索引是否建成、覆盖范围是否完整，再判断检材没有该线索。检查返回结果是否分页、截断。
- 先在解析结果中定位，再到原始文件复核。解析表未列出消息或文件时，检查应用私有目录中的原始数据库、动态会话表和缓存。导出 SQLite 时同时保留对应的 `-wal`、`-shm`；只读打开工作副本。批量导出已定位的目录，保存复制清单，避免重复逐文件提取。
- 检索由题干关键词扩展到同义词、包名、文件名、字段名，再缩小到相关账户和时间段。大目录先盘点类型、数量和大小；限制输出、保留完整路径并记录搜索覆盖范围。一次有限扫描未命中，不能写成“整个镜像不存在”。
- 以原始记录的字段、行号、文件路径或哈希支撑结论。截图、OCR、AI 提取的数字须回看原图；参考 WP 的答案必须回到相同检材中验证。两份 WP 即使一致，也可能沿用了同一错误。

## 易错题的核对

- **身份与交易：**先确认手机本机账户和聊天双方。地址出现于聊天，不等于属于嫌疑人；结合消息发送者、收付款方向、金额、时间及交易记录区分付款地址和卖家收款地址。只有一个对方收款地址时，不据此回答嫌疑人钱包。任何外部查询须遵守用户授权与工具审批，不能为求证把检材中的地址或秘密直接发送到第三方。
- **文件与程序：**给压缩包、包内文件、外层程序、解压副本、PE 资源及释放程序分别记录文件名、大小和哈希。题目问哪一层，就计算哪一层的原始字节。壳或压缩标识遭改动时只修改分析副本；静态确认程序功能、端口和释放资源，不运行可疑 EXE。编程语言要判断题目所指的释放程序，不能以外层程序或其打包器代替。
- **图片与金额：**先用相册数据库或目录盘点全部相簿，不预设只有 `DCIM/Camera`。逐图核金额、收款人、时间和可用的交易编号；文件哈希可排除完全相同的文件，但不同文件是否对应同一笔转账需更强依据。相同金额或分钟不足以自动合并。并列计算“全部图片金额”和“明确去重后金额”，列出排除项目及理由；出现固定差额时回查漏图和读数，而非补差猜答案。
- **应用记录与时间：**区分已发布作品、草稿、观看历史与重复缓存；按作品 ID 找对应统计字段。区分原始时间戳、UTC 和北京时间，按题目要求转换。数据库中的相似秘密（例如开机密码与磁盘恢复密钥）按用途分别归属。
- **流量与日志：**先确定攻击者、受害者和时间范围，再按会话、请求与响应、日志成功/失败状态交叉验证。计数题明确去重单位是包、请求、会话、IP 还是文件；不能凭单条命中推断全局。

## 给答案前与判错后

提交前检查：对象和归属正确；原始证据可定位；统计范围及去重规则明确；后缀、进制、大小写、单位、时区符合题干。必要时用第二条独立证据复核高风险答案，如钱包归属和汇总金额。不要为了形式上的双证据而重复同一数据库的派生结果。

按用户指定方式输出；若要求每解一题就答一题，应及时给出答案及简短依据。未解决的题说明具体缺口，不用候选值冒充定论。

若用户反馈答案不对，立即撤回原结论，先检查主体、对象、范围和格式，再复核原始证据与计算过程。保留旧答案作为错误假设，记录为何被排除；比较参考 WP 时解释差异来源。没有找到差异前，不把另一个 WP 的数字或大小写直接宣布为已通过答案。
