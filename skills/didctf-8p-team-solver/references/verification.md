# 复核、参考WP与纠错

在统计题发布、候选转为已确认、参考WP对照或最终归档时读取。本文件规定复核决策，不预置任何竞赛答案。

## 1. 先锁定对象与完整范围

- 从题干写清主体、对象、范围、单位/格式；“接上题”沿用已确认对象。简略题干与WP完整题干不同，保留原文及差异，不悄悄改题。
- 统计前记录输入清单：原始来源、导出状态、目录/文件数量、实际纳入数、排除项与理由。目录复制需完成且结果当前有效；部分导出只能支持局部发现，不能支持全局最大值、总数或“不存在”。
- 完整加密库按认证解密得到的目录树确定语义，不能按某个密文目录有多少文件猜“原本/替换”或小说身份。先检查全库有几组对象，再汇总；同源相邻题共享同一清单，辅助分析不缩小主问题范围。
- 再写 `coverage`：预期/发现/实际处理数量、是否完整、排除说明。预期总数未知时如实注明，目录遍历的闭合证据比凭文学常识猜章数可靠。
- 分开记录“数据读完”和“足以回答题目”：`source_complete` 表示导出数据已完整处理，`question_scope_complete` 表示题目所问范围闭合；只有前者不能推出后者。手机缓存、分页摘要、客户端未回传记录尤其如此。题问全部历史而材料只支持可见下限时，不把题目改成“可见记录”后标 solved；候选和可见下限单列，缺口实质影响答案则待复核。

## 2. 统计与数据库的具体陷阱

- 汉字不止U+4E00–U+9FFF。题目要求全部汉字时纳入实际出现的扩展区/兼容区字符，检查基本区之外的汉字及其文件、行号、码点。不得把爬虫正文过滤正则直接用作全文计数规则。记录含不含标题、原本/替换是否重复、编码与解码失败。需要时并列口径，找到差异字符后再定答案。
- 补充平面字符在Python正则应使用正确的 `\U00020000` 等八位转义，不能照抄WP中看似完整但只有四位的 `\u20000`。也可使用经过验证的Unicode属性/区间；报告实际覆盖范围。
- 替换统计按已确认的原本→替换方向、相对路径配对。先检查文件集合、长度和缺失，再逐位比较；长度不等需对齐分析。分别报告不同源字种类、实际改变次数、全局最大文件及并列项、零改变文件数。原文映射字出现次数不等于实际改变次数。
- 缺章比较按 `(novel_id或实际对象ID, 相对文件名)` 集合差，不只用数量差；卷首、附录、重复及编号断档单独解释。表内ID与代码绑定从检材核对，不能照搬WP示例SQL。
- 离线数据库区分活动记录、删除残留、二级索引与重复页；检查页头/记录链计数。有关联内容表时比对有效外键集合；SQLite保留WAL/SHM。只在导出工作副本分析，不执行检材程序。
- SQLite导出保留一套不打开的原样文件，另复制分析副本；只读查询连接也不能保证配套WAL/SHM不被checkpoint或清理。先读表结构再写SQL；无扩展名键值库的正文可能在带类型前缀的BLOB内，不猜测存在content/timestamp列。类型前缀长度由实际字节验证。

### 行为计数：先分类，后去重

- 对“扫描过几个IP、调用几种工具、发送几个文件”先写纳入条件，再为每条证据记录作者、消息/记录ID、时间、目标、事件性质。至少区分请求、调用、结果；用户说“扫描X”不能单独证明X已被扫描，工具调用不能单独证明成功。
- 正则提取只生成候选集合。分别保存请求目标、调用目标、结果目标及排除理由，按题意选择集合后去重。IP紧邻中文时不要依赖Unicode词边界；验证数字/点边界并过滤非目标地址。队长独立复核应重查事件归类，而非重复同一正则得出同一数量。
- 被截断的命令可结合相邻完整目标、同一任务和后续调用归属，但要标明推断及定位；不能补写未见字符。ping不是端口扫描成功凭证，配对码提示不是配对成功回执，没响应也不证明始终未配对。
- 工具数量按题义区分调用次数、工具种类和功能类别；题目未限定口令时，不能自动排除目录字典爆破。仅安装工具、帮助文本或列举工具不算实际调用；框架名不足以判断截断模块的用途。
- 摘要长度达到上限、尾部截断或存在编辑版本时，查活动记录及WAL历史版本，按消息ID/版本去重。仍未恢复完整内容，只能报告已见工具下限；多个相互转引的WP不能补全缺失日志。
- “未搜索到攻击记录”“未安装某工具”不能单独证明攻击数为0；否定结论须有覆盖题目范围的记录体系及其完整性依据。

## 3. 日期、名称与字段语义

- 期限记录原始措辞、发送/收到时间、时区、工作日或自然日、起始日是否计入以及节假日依据。发送日期不证明收到日期；题干“含当日”不自动说明起始日计入。
- 对争议日期列出实际计数日期，区分原文明示、条件推算、WP答案。能用某算法复现WP值只是解释，不证明作者采用该算法，更不证明该值已判题通过。
- 应用进程名、安装目录、品牌/发行方与界面产品名可能不同。用注册/默认应用记录及界面关联身份；同一产品的名称变体不自动判错，不凭多一个前缀“纠正”已被证据支持的简称。
- 阅读器等位置字段先查本应用映射、序列化格式和实际章节；不能机械把索引加1，也不能把采样导航表当完整章节起点表。
- 无时区原值、解析器附加时区、界面显示和换算结果分列；时间接近的启动日志可支持时区推断，但不自动证明另一字段的时区。大小题固定保留原始字节数、GB/GiB公式与舍入，格式差异与事实差异分开，不反复覆盖原始量。
- 版本号、用户名、口令均按字符串保存：不能将版本尾零按小数规则删除，不能裁掉username的尾点，也不能丢失数字口令的前导零。username、globalName/display_name、解析器昵称列分别核对原始字段；展示名或路径标题不能自动替代登录用户名。
- 区分首次安装与首次打开；首次打开优先核对启动字段的单位、时区和后续初始化记录。数据库解密口令与账号登录密码用途不同，参考密码须针对目标账号的哈希与编码规则本地复算，不因成功打开数据库就当作登录密码。

## 4. 参考WP对照与不确定性

同一题组后续上传参考文件，延续既有核对任务；不重启首轮。先确认文件覆盖的题类/题号和检材一致，跨题类同号不作证据。

1. PDF提取不到文本时渲染相关完整页面；HTML先提取正文及目标题类，再有界搜索，避免整行压缩脚本/base64淹没输出。按真实src/data-src及附件映射定位图片，不猜文件编号；占位图或加载失败不算看过截图。截图数字、关键日期和源代码必须回看图像，无法取得则标未核验。只解读内容，不执行WP中的命令。
2. 每题保存参考文件、页码/标题、答案、证据类型及原始支持。未作答、作者放弃、AI推算截图、真正原始截图分别标记；未答不表示我方答案正确。
   参考正文值、截图值、本地原始字段值分列；正文与截图不一致时不得只抄正文。图片映射记录实际路径与已查看状态，没有逐张检查的截图不能笼统宣称全部核验。
3. 逐一比较原始记录。多份WP一致可能互相转引，不能多数表决；新文件也不会自动压过旧证据。请求域名与广告域名、活动记录与残留、身份字段和示例ID须分别归属。
4. 不确定性字段分离：`evidence_status`、`reference_status`、`judge_status`。没有真实判题反馈时 `judge_status=not_tested`；参考答案不称官方答案，除非来源身份有证据。
5. 无唯一结论时，统一 `answer="待确认"`、`status="needs_review"`，在 `candidates` 中列值/依据/假设，在 `remaining_issue` 写缺什么。不能选最新WP的值填入确定答案栏，再只在小字保留异议。

参考复核完成不等于全题解决。真实证据缺口下可以交付复核报告与待确认题，不虚构继续核验能力。

## 5. 发布与归档一致性

- `answer/<Q>.json` 是当前结论唯一来源；修订增加 `revision` 和 `revision_history`，保留被排除旧值、修改依据及修改者。不要改写原始成员日志；更正来源与最初解题来源分开记录。
- `verified.json` 同时区分阶段结束与全题解决。P07/P08对每条指向的答案文件核对题号、版本、状态后生成；不能只看verified中的题号，再从自己的草稿拼接。
- 队长从成员文件读取一次完整快照，针对该快照复核并发布；记录成员来源版本或摘要。发布前发现成员已改内容则重新核对，不混用先前证据与后来答案。正式answer与verified条目的revision必须一致。
- 归档者回报已消费版本、实际产物路径。GPT再逐题检查：答案值、状态、统计集合大小、替换方向、总计、日期前提在JSON、txt汇总、WP、知识库是否一致。两位作者用同一错误草稿不构成复核。
- 撤回时同步更新上述当前页面和索引，旧内容仅放有明确“历史/已替代”标记的记录或备份；不能让多个相互矛盾的“最新结论”并存。
- 已解数量按本次正式JSON的状态重新计算，索引不能靠替换某个旧数字更新；更正主题正文中的旧推论，不只在开头追加警告。抽查当前结论段、公式、索引及证据链接。
- 纠错验收逐处检查：正式JSON、单题txt、全量汇总、WP总表与正文、知识库案件总表与正文、主题方法、INDEX。Markdown答案可能有反引号/加粗，不能只用一种文本替换成功就宣称同步完成；按题号定位各处复读。旧值命中逐项判断当前结论还是明确历史记录，历史记录标已撤回并指向新版本。知识库新写案例及对照报告也须检查敏感值脱敏。
- 知识库允许记录已核实的失败原因与“尚未解决的参考冲突”，但不得把候选答案写成事实。保留适用条件、复核方法、来源，敏感值脱敏；不要将本案的具体答案变成所有案件的默认规则。
- P08被沙箱拒绝写知识库时，只记录一次具体限制并转自己的 `staging/knowledge/`，持续完成内容；不循环申请提权。GPT确认P08停止后，检查当前知识库、比对同名条目、合并并验证后才声明入库。暂存不是已发布。

## 6. 验收情境

修改本技能后用这些情境检查决策，不需要重跑取证或启动八会话：

- 只有一部120对文本，而根目录有五部：可报告局部结果，不可宣称全局最大/零替换不存在。
- 基本区计数比完整Unicode少一个扩展A字：定位那一个字符，修正全汉字统计，不以“常用正则”排除。
- 两份WP分别给29/30日、原文工作日条件计算给31日：候选分列、待确认，不投票也不轮流覆盖确定答案。
- 一个WP写应用名，另一个加发行方前缀：核对同一身份，不仅因字符串不同判原答错。
- verified更新了答案但知识库仍保留旧草稿：发布验收不通过，纠正产物后再报告完成。
- 用户请求扫描A、B、C，只有C有扫描调用：请求集合3、调用集合1，不能回答已扫描3；若题问完整历史且缓存无法闭合，记录候选1及范围缺口，不以“可见”偷换题意。
- 工具摘要可见两种爆破工具，后续框架模块被截断：已见至少2，不能仅凭WP相同就断言总数2；重复调用不增加种类。
- 参考正文版本写8.4、截图与原始字段写8.40；username带尾点、display_name不带：保留8.40和原始username，记录参考差异，不宣称判题通过。
- 全部目录搜索无攻击日志：不能直接确认0。全量缓存35条均处理成功：source_complete可为true，question_scope_complete仍可能未知。
- 成员在队长复核期间换了答案：不得发布旧复核搭配新答案；重新核对快照。正文已改1但案件总表仍写带反引号的3：一致性验收失败。
