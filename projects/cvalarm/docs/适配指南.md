# 模型与数据适配

本版提供接口和异常处理。没有真实视频、权重和模型服务，因此未验证真实推理质量。所有输入应与同一机位、同一视频时轴对应；不能把另一场景的合成检测结果和真实图像拼在一起用于正式评价。

## 检测结果 JSONL

逐行格式：
```json
{"camera_id":"CAM-01","frame_idx":0,"ts":0.0,"ok":true,"detections":[{"cls":"person","bbox":[0.1,0.2,0.3,0.7],"score":0.91}]}
```

bbox 是归一化 xyxy；ts 为相对视频起点的秒；按机位时间单调递增；解码/采集失败使用 ok=false，不用空检测冒充正常帧。gt_label 可选，缺失表示没有帧标签，不会自动当负例。检测器的跟踪 ID 不直接复用，本工程有自己的参考跟踪器。

--cameras JSON：
```json
{"cameras":[{"camera_id":"CAM-01","fps":2,"width":1920,"height":1080,"rois":[{"roi_id":"ROI-A","polygon":[[0.2,0.2],[0.8,0.2],[0.8,0.9],[0.2,0.9]],"event_class":"UNAUTHORIZED_INTRUSION","dwell_threshold_s":45}]}]}
```

--gt 事件真值 JSONL：
```json
{"event_id":"E1","camera_id":"CAM-01","event_class":"UNAUTHORIZED_INTRUSION","roi_id":"ROI-A","start":100,"end":200,"satisfy_ts":145,"evidence_span":[100,200]}
```

省略 --gt 表示事件指标不可评价；提供空文件表示该数据已标注且无正例。独立测试还要求测试段有可评价正例。

```bash
python run.py run --source jsonl --frames data/frames.jsonl --cameras data/cameras.json --gt data/events.jsonl --config config/site.json --out runs/replay
python run.py test-report --source jsonl --frames data/frames.jsonl --cameras data/cameras.json --gt data/events.jsonl --config config/site.json --state-dir state/replay-test
```

自行设置 protocol.dev/test 的半开区间 [start,end)，同机位不重叠，真事件不要横跨边界。检测框可从 Ultralytics 的 boxes.xyxyn、conf、cls 导出；这是适配建议，本工程未内置 YOLO 原生执行器。参见 [Ultralytics 官方推理文档](https://docs.ultralytics.com/modes/predict/)。

## 定位服务

stage2.scorer.kind 支持 heuristic、external、http。external 的 path 指向：
```json
{"CAM-01":[[0,0.1],[1,0.2],[2,0.8]]}
```

external 为离线回放分数，使用最近时间点；正式实验需确保分数由因果窗口生成，文件本身无法证明模型是否读取了未来帧。

http 发送本工程定义的协议：
```json
{"schema_version":1,"candidate_id":"...","query":"person remains in the designated region","camera_id":"CAM-01","window":[0,60],"available_until":60,"frames":[{"ts":30,"frame_idx":60,"sha256":"...","url":"data:image/jpeg;base64,..."}],"bins":[{"start":0,"end":1}]}
```

响应必须为 {"scores":[0.1,...]}，与 bins 等长，每项为有限的 [0,1] 数值。缺文件、缺机位、连接失败、非法概率不能默默返回零；运行时故障记录 SYSTEM_ERROR。配置 endpoint、timeout_s、api_key_env、model_id、model_revision；queries 按事件类别设置实际查询语句。

这是外部模型服务适配契约，**不是 VideoJev 官方 HTTP 接口**。官方项目通过 Python 推理接口处理视频及 grounding 查询，服务端需要另行完成时间采样和概率对齐，见 [VideoJev 官方仓库](https://github.com/MCG-NJU/VideoJev)。本包不附该服务、权重或 CUDA 环境。

## 视觉证据与 Qwen 类 VLM

配置 stage3.verifier=vlm、stage3.vlm.endpoint 为完整 chat/completions URL、model 为服务中的实际名称。直接传 --vlm-endpoint 也会启用 VLM。服务必须支持 image_url 和 JSON Schema 响应格式。各服务兼容程度需实测。

图像可来自：
1. stage3.vlm.frames_manifest 指向 JSON：{"CAM-01":[{"ts":30,"frame_idx":60,"path":"frames/000060.jpg"}]}。图片路径相对该文件，支持 JPEG/PNG/WebP。
2. deployment.media.cameras 指向视频，通过可选 OpenCV 解码；路径相对 deployment.media.root，后者相对工程根目录/安装版当前目录。

只抽取候选窗口内且不晚于触发时间的帧。配置 max_frames 限制抽样数。post_roll 尚未到达的部分标 pending，不虚构已经等待或读取到了未来画面。文件解码 API 依据 [OpenCV VideoCapture 文档](https://docs.opencv.org/4.10.0/d8/dfe/classcv_1_1VideoCapture.html)。

模型输出的事实、规范依据、原结论保存在 model_result；事实引用的帧号必须出现在输入帧清单。候选机位/类别和时间窗均会核对。与规则不一致、授权资料不足、视觉输入缺失或模型错误时转人工。真实图像不合格、模型乱编事实仍需人工和独立数据检验，结构检查不能保证视觉事实正确。

## 授权、反馈与安全相关边界

授权 JSON 格式保留 permits，并必须明确写 complete:true，表示记录覆盖当前评价域；否则“没查到许可”只能判定未知。内置 authorizations.json 标为 synthetic-demo-only，不能用于真实回放。配置无授权文件时，UNAUTHORIZED_ 类不确证。

服务看板 POST /api/feedback 的主体包含 run_id、alarm_id、verdict(confirm/dismiss/uncertain)、operator、reason_code、note。dismiss 必须有合法理由。服务核对当前运行和真实存在的已显示告警，并从原告警提取机位、类别及规则版本；相同提交去重。GET /api/feedback 仅返回当前运行记录。

服务默认监听本机，仅用于开发复核。没有交付生产身份认证、分布式反馈锁或实时监控平台。原有 privacy 配置不是已实现的图像脱敏/留存清理功能；真实媒体使用者需另行落实这些功能。

重开已有运行的看板时，反馈校验、默认状态路径及媒体映射读取运行快照。迁移后可用 --state-dir 指定新的状态位置；提供非空 deployment.media.cameras 配置可显式重映射媒体位置。错误模型结果已经发生的 Token 消耗仍记账，http_attempts 记录尝试次数。
